# 制作流程与质检

## 1. 参考分析与素材索引

先写参考片的“可观察现象—剪辑作用—可执行实现”，保留推测边界。ref3 的关键经验是四层同步：段落能量、乐句语意、动作接触、效果峰值；并非套用同一个滤镜。原动画已有的烟尘、镜像、运动模糊不能一律记作混剪新增效果。

素材索引建议记录：`source_id`、文件、分辨率/帧率/时长/色彩信息、有效源入点和长度、内容、动作峰、主体中心、负空间、硬字幕区域、是否跨原始切点、建议故事位置。大文件先每数秒或按场景取样，候选窗口再提高抽帧密度；一个中点无法证明整段干净。

压缩包用用户已给密码解压并检查 CRC/文件完整性。旧总集篇换为单集时，用多个连续帧确认对应位置，重新核对画幅、字幕、帧率和源区间；名称相似或单帧相似不能证明精确配准。V2 曾将 73 个总集篇镜头逐镜配准到 ZIP 来源，这是可复用的迁移方法，而非把同一偏移应用于所有镜头。

对每个源按时间排序检查无意重复。重复意象可用不同镜头；需要刻意回忆复现同一源区间时，明确记录用途，而不是建立“一律禁止重复”的全局创作规则。

## 2. 规划与数据

输出建立固定帧率、分辨率和色彩目标；原生帧率可以不同，先决定重采样方法。用整数帧定义 `[start_frame, end_frame)`，切点前后共享边界。源时间仍以源秒数表达。

每个镜头同时保存来源、变速映射、取景、调色、效果、蒙版及文字构图依据。故事章节、歌词识别、实测重音独立保存，便于改某一镜头而不丢音乐依据。见[字段与工具](timeline-and-tools.md)。

V3 案例是 1920×1080 / 30fps / 5207 帧；完整歌曲约 173.539 秒，画面到 173.567 秒。这个差额小于一帧；音轨不需要为凑整数帧而随意变速。更换音乐后必须重新计算。

变速映射描述“输出归一化时间 → 源归一化时间”。动作峰可落在附近实测重音上，但映射应保持时间单调、保留动作的前后可读性。最近原帧取样能避免动画线条的混合重影，强慢速会产生重复帧，必须用实际播放判断；光流插帧也需要检查脸、手、刀和发丝。

## 3. 代表样片先行

先试几种风险不同的组合：

- 冷暗脸部 + 小字：检查黑位、肤色、手机尺寸阅读。
- 动作 + 短重音字 + 几何合拢：检查字是否被整个入场效果吞掉。
- 人物遮字 + 漫画背景 + 动态黑边：检查轮廓、层序和相机一致性。
- 墙面或地面透视长句：检查角度、行宽、运动与真实可读时长。

样片用于决定强度和构图，确认后才扩展全片。换素材时撤销或重新验证旧的蒙版、漫画窗口、透视四边形与动作峰，避免只换视频路径。

## 4. 渲染缓存与组装

分镜渲染适合并行和局部返工。先冻结一次时间线和引擎版本，再启动工作进程；不要一边渲染一边改模块而让同一交付混入两个版本。

缓存签名至少覆盖：

1. 当前镜头全部参数。
2. 与镜头相交的文字内容、词界与布局。
3. 转场依赖的前驱镜头最终画面状态；其中包含前驱文字/素材/参数的变化。
4. 视频、漫画、蒙版等实际资产的身份与版本（路径、大小、时间戳，或更强的内容哈希）。
5. 引擎及效果代码。

只用镜头文件名或时间线总时长判断缓存有效会漏掉文字、资产和代码修改。合成前再次核对缓存签名及每段帧数，转场出端变化还可能使相邻缓存失效。

拼接后按输出帧编号建立连续 PTS，避免多个容器时长的舍入误差累积。V3 使用 `setpts=N/(30*TB)` 配合固定 30fps；其它帧率应相应替换。编码可使用可用的硬件编码器或 CPU `libx264`，不要把某张显卡当作 skill 的必需条件。

SDR 输出采用一致的 BT.709 流程。HDR 输入应先检查色彩标记和转换；仅写入 BT.709 标签并不会完成色调映射。

## 5. 四层质量检查

| 层次 | 应检查 | 不能据此宣称 |
|---|---|---|
| 数据 | 时间线连续、源不越界、帧位坐标、歌词映射、参考文件存在 | 最终文字一定可读 |
| 缓存 | 当前参数签名、片段帧数、转场前驱依赖 | 最终封装没有音画问题 |
| 成片数值 | 实际 MP4 完整解码、尺寸、帧率、总帧、轨道、PTS、音频同步/峰值 | 全片视觉已人工观看 |
| 视觉与视听 | 首/中/末、文字起落、动作峰、蒙版边缘、逐帧效果、正常速度段落审片 | 抽帧等同连续人工看听 |

歌词检查要覆盖从原始短句到词组、再到构图区间的关系，不能只统计文字事件数。用最终渲染后字形包围盒查边缘，检查人物遮挡后的可见文字比例；数值异常是审片提示。最短歌词需要逐帧看“何时出现—落定—何时消失”，透视缩小、黑底、转场和前景遮挡都可能让理论时长失去阅读价值。

暗黑风格的黑场检测可能把设计中的窄缝、线稿、短闪帧和水下暗镜误报；从候选前、中、后抽帧，结合时间线逐个说明，不能看到日志就一律删除黑场或忽略所有黑场。

指定原曲独占音轨时，明确映射音乐，避免把原片对白混入。用分散在全曲的多个窗口对照实际成片解码音频；相关系数能辅助发现错位，不是完整听觉质量评估。再检查立体声峰值。V1–V3 此曲使用 0.66 线性增益解决解码峰值过高；这是该文件的实测选择，不是所有音乐的标准音量。

## 6. 版本保全与交付

开始前记录需保留文件的大小和 SHA256，在独立目录写新产物，交付时复核旧成片哈希。目录可按“制作工程、素材索引、音乐分析、漫画素材、渲染缓存、预览、质检、成片”组织，但可服从用户现有结构。

交付说明包含最终文件、规格、创作变化、来源范围、运行入口、依赖及检查范围。保留源区间、参数、逐词证据与不确定性。FCP7 XML 若引用的是已合成镜头，只提供镜头重排和独立音轨；不能称为可逐图层修改的 AE/PR 工程。

本仓库公开的是方法、轻量工具和少量成片截图；原工程的完整媒体、音频、歌词数据库与重型缓存仍留在制作目录。
